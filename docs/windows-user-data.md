# Данные и обновление Windows

Обычный запуск Windows-клиента использует `%LOCALAPPDATA%\greenrhythm\config`. Подписки, профили, схемы маршрутов, настройки, локальные базы и защищённая идентификация устройства живут отдельно от exe. Распаковка следующего выпуска в новую папку не создаёт ещё один набор профилей. Режим переносной копии остаётся доступен через `-portable` или файл `portable.flag` рядом с exe.

## Первый переход со старой версии

Если общий каталог ещё пуст, клиент ищет данные в `config` рядом с запущенным exe, затем в прежних каталогах из распознанного автозапуска GreenRhythm этого пользователя. Предпочитается источник с профилями, настройками или идентификацией устройства. Произвольный поиск по диску не выполняется. Если старая папка нигде не зарегистрирована, для переноса сначала запустите новую полную сборку из прежней папки приложения.

Перенос создаёт отдельную временную копию, сверяет SHA-256, повторно проверяет исходный набор файлов и только затем публикует целую папку `config`. Подписки, пользовательские маршруты и неизвестные поля копируются без преобразования. Исходная папка остаётся на месте. Текущие `temp` и `neko.log` не переносятся. Ссылки, junction и пересекающиеся каталоги отклоняются. При ошибке или изменении исходных файлов новая пустая конфигурация не запускается.

Существующий непустой общий каталог является основным: содержимое другой копии в него автоматически не подмешивается. Это предотвращает возврат к старым маршрутам и подпискам при случайном запуске exe из «Загрузок». Старая работающая копия из обнаруженного каталога блокирует первый переход; новая программа просит полностью выйти из неё и сама не отключает соединение. Пока новая программа работает, она удерживает блокировки обнаруженных прежних каталогов с тем же токеном локального канала. Повторный запуск старого exe передаётся в текущее окно, вместо запуска второго ядра.

Откат программы не перемещает данные обратно. Помощник передаёт выбранный каталог через `-appdata`, в том числе при запуске прежней версии. Перенос защищённой идентификации рассчитан на того же пользователя и ту же Windows; это не экспорт на другой компьютер.

## Автозапуск

Клиент проверяет путь exe, рабочую папку и параметры собственной задачи планировщика. При запуске с правами администратора уже включённый автозапуск переводится на текущую копию и выбранный каталог данных. Устаревшая запись Run распознаётся как включённая и может быть заменена задачей, вместо того чтобы считаться выключенной из-за несовпадения пути.

Автозапуск не включается сам, если пользователь его выключил. Для изменения существующей задачи требуются распознанный exe GreenRhythm и совпадение пользователя/SID. Неизвестная, повреждённая или чужая задача не перезаписывается с `-Force`. Если собственную прежнюю задачу исправить не удалось, вторая запись Run не добавляется.

## Установка обновления

Проверка выпуска и предложение установить его доступны с AppData. Установка остаётся явным действием: программа не отключает работающий профиль при одном обнаружении новой версии. Загрузчик из каталога данных получает отдельно абсолютные пути установки, данных и архива. Эти пути сохраняются при запуске временной копии загрузчика и при откате.

Помимо подписи и контрольных сумм, до замены файлов проверяются непустые `geoip.db` и `geosite.db`. Неполный архив не меняет рабочую установку. Если базы отсутствуют у уже запущенной старой копии, ошибка указывает её фактический каталог и необходимость проверить автозапуск; она не утверждает без проверки, что скачанный архив повреждён.

Реестр используется для регистрации запуска, а сами профили остаются обычными файлами в AppData. Их не нужно превращать в значения реестра для сохранения при обновлениях.

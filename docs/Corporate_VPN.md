# GreenRhythm и рабочий VPN на Windows

При включённом TUN прямое соединение с внутренним адресом следует маршруту
Windows. Если рабочий VPN уже установил маршрут к этому адресу, GreenRhythm
использует его адаптер. Это действует для TCP и UDP, в том числе внутреннего
DNS. Ядро проверяет маршрут при создании нового сокета, поэтому после
переподключения рабочего VPN не требуется вписывать новый индекс адаптера.

Правила, выбирающие прокси, блокировку или явный сетевой интерфейс,
сохраняют действие. В стандартной RU-схеме внутренние адреса уже включены
в «Напрямую» через `geoip:private`. В собственной схеме нужно проверить,
что более раннее правило по домену или процессу не отправляет рабочий
ресурс через внешний прокси.

## Внутренний DNS

Рабочий VPN не всегда сообщает DNS-суффиксы или политику разрешения имён.
Публичный DNS тогда отвечает, что внутреннего имени нет. Укажи известные
рабочие зоны и DNS-сервер VPN в настройках маршрутизации, в блоке простого DNS:

1. В «DNS-домены локальной сети и рабочего VPN» добавь зоны по одной на строку,
   например `corp.example`. Правило включает сам домен и его поддомены.
2. В поле ниже укажи IP DNS-сервера из настроек рабочего VPN, например `10.0.0.53`.
3. Сохрани настройки и примени конфигурацию в удобный момент.

Только указанные зоны используют этот сервер. Их адреса разрешаются до
выбора маршрута, чтобы правило внутренних IP могло сработать. Остальные
сайты используют прежние DNS-правила и сервер по умолчанию. Настройки DNS
Windows и рабочего VPN не перезаписываются. Если включён пользовательский
объект DNS, эти поля не применяются: правило добавляется в собственный объект.

Рабочий VPN должен быть подключён и предоставлять маршрут к DNS-серверу
и самому ресурсу. GreenRhythm не создаёт маршруты корпоративного VPN.

## Проверка

В PowerShell проверь внутренний адрес и DNS, подставив адреса своей организации:

```powershell
Find-NetRoute -RemoteIPAddress 10.0.0.42
Resolve-DnsName gitlab.corp.example -Server 10.0.0.53 -DnsOnly
```

Первый вызов должен выбирать рабочий VPN, второй — возвращать внутренний
адрес сервиса. Проверь ресурс через локальный прокси GreenRhythm:

```powershell
curl.exe --proxy http://127.0.0.1:2080 https://gitlab.corp.example/users/sign_in
```

Если Windows выбирает правильный VPN, а имя разрешается на публичном DNS,
проверь рабочую зону и IP сервера в настройках GreenRhythm. Если выбран
неверный маршрут, сначала проверь состояние рабочего VPN. Ошибка доверия
сертификату требует установки корпоративного CA по инструкции организации;
отключать проверку сертификата в клиенте не требуется.

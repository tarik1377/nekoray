# Возврат предыдущей версии Windows

В «Подробных настройках», раздел «Прочее», есть кнопка **«Откатить версию»**. Рядом показаны версия и источник: подписанный выпуск либо проверенная локальная сборка. Кнопка включается только после проверки предыдущего снимка и текущей установки. Ошибки проверки показываются рядом с кнопкой.

Возврат меняет файлы программы, ядра, установщика, Qt и остальных компонентов. Он **не копирует, не восстанавливает и не удаляет** пользовательские настройки, подписки, профили и схемы маршрутизации. Исключена вся папка `config`, включая встроенные `.srs`. Неизвестные поля и неизвестные JSON-файлы профилей также остаются на месте.

После подтверждения GUI сначала копирует установщик в отдельный временный executable и сверяет байты. Только успешный запуск этого помощника запрашивает закрытие клиента. Помощник показывает проверку, ожидание освобождения файлов, замену и запуск. Если сохранённая версия не запускается, транзакция возвращает текущие файлы и пытается запустить текущую программу. Такой случай сообщается как неудачный откат, а не как успешное восстановление.

## Сохранение и проверка

При установке подписанного обновления формируется `.greenrhythm-installation.json`. Он содержит платформу, версию, исходный подписанный манифест и SHA-256 каждого установленного файла программы. Если предыдущая установка имеет такой подтверждённый манифест и все её файлы совпадают, установщик сохраняет её в `.greenrhythm-previous/files` с отдельным `manifest.json`. Пользовательские файлы туда не входят.

Снимок проверяется при показе кнопки и повторно перед возвратом. Обязательны Windows x64, совместимый формат настроек, полный набор компонентов, безопасные относительные пути, размеры и совпадение SHA-256. Снимки старше `1.9.2.2`, неизвестное происхождение, чужая платформа, несовместимый формат, повреждённые файлы и ссылки не допускаются. Файлы программы, появившиеся только в текущей версии, удаляются в той же транзакции, чтобы старый Qt не подхватил несовместимый новый plugin.

Предыдущая версия не становится «проверенной» просто из-за наличия файлов или checksum рядом. Обычная установка по-прежнему требует подпись выпуска с ключом, закреплённым в установщике.

## Явная регистрация проверенной локальной сборки

Служебный режим предназначен для оператора, который уже проверил конкретную локальную сборку. GUI его автоматически не вызывает. Receipt принимает `version`, `source_commit`, `go_toolchain`, `qt` и `files` с `file`/`sha256`, как в локальном build receipt:

```powershell
C:\GreenRhythm\updater.exe --register-previous-local C:\Builds\1.9.2.2\build-receipt.json C:\Builds\1.9.2.2\GreenRhythm
C:\GreenRhythm\updater.exe --register-current-local C:\Builds\1.9.2.3\build-receipt.json C:\Builds\1.9.2.3\GreenRhythm
C:\GreenRhythm\updater.exe --rollback-info
```

Режим не останавливает клиент. Он сверяет SHA-256 полного набора компонентов, PE x64 для GUI/ядра/установщика и фактически встроенный `go1.26.9` для Go-компонентов. Короткий вызов ядра `--version` проверяет поддерживаемый номер ядра без запуска профиля или TUN. Компонент ядра может сохраняться при обновлении только GUI; его номер хранится отдельно от версии пакета. При регистрации текущей версии дополнительно проверяются файлы непосредственно в установленном каталоге.

`source_commit` и версия пакета здесь являются явной операторской аттестацией из проверенного build receipt. У старых локальных бинарников revision не встроен, а PE-версия GUI была постоянной `1.0.0.0`; механизм не выдаёт эту аттестацию за криптографическую подпись. В UI такой источник обозначается «проверенная локальная сборка».

Прямой запуск возврата возможен через `updater.exe --rollback`. Он использует тот же проверяемый снимок, блокировку установки, ожидание освобождения файлов и видимое окно, что и кнопка.

## Границы проверки

Установщик проверяет, что запущенная программа остаётся живой две секунды. Это выявляет loader errors и немедленное падение, но не доказывает работоспособность VPN. Механизм не выполняет сетевой тест и не гарантирует поведение отдельных сайтов после возврата. Совместимость старой программы ограничена объявленным форматом настроек; последующая работа старого клиента остаётся поведением той версии.

При незавершённом восстановлении занятые резервные файлы сохраняются в `.greenrhythm-backup-*`, а следующая установка отказывается молча их перезаписывать. Прерывание питания требует проверки этих резервных файлов; автоматического восстановления после отключения питания нет.

Регрессии проверяют реальные файловые блокировки Windows, повреждение checksum, заблокированный прежний снимок и аварийный backup, все позиции ошибки замены, неудачный запуск возвращаемой версии с возвратом текущей, неизвестные профили и отсутствие пользовательских файлов в снимке. Qt offscreen проверяет состояние кнопки, источник версии, ошибку запуска помощника, проверку его копии и асинхронный ответ CLI.

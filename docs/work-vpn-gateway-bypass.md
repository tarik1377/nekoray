# Рабочий VPN внутри виртуальной машины

Обычный выход DIRECT выбирается после перехвата пакета TUN. Он не равен
исключению из таблицы маршрутов ОС. Для NGate в VMware NAT проверка TCP/443
сама по себе не доказывает прохождение протокола или авторизацию сертификатом.

В настройках Windows-клиента и в «Маршрутах» добавлена кнопка **«Рабочие VPN
и виртуальные машины»**. Введите домен шлюза, IP или CIDR с новой строки.
Можно вставить HTTP/HTTPS URL: используется только имя узла. URL с учётными
данными отклоняется. Исключение действует на все порты полученного IP.

Используется существующий параметр `vpn_route_exclude_extra`. Окно показывает
прежний список целиком, сохраняет его атомарно без изменения схем маршрутов
и не переподключает профиль. Отмена и «Готово» без изменений ничего не записывают.
Новые исключения действуют при следующем подключении. Старое поле в настройках
TUN тоже принимает домены, IP и CIDR и проверяет их до изменения настроек.

Перед созданием TUN ядро разрешает домены через системный DNS с общим пределом
10 секунд. Используются все полученные A/AAAA. Имена проверяются заново при
каждом запуске, с обычными правилами кеширования DNS Windows. Полученные /32
и /128 добавляются в `route_exclude_address`; остальные правила, DNS и выходы
не меняются. CIDR-конфигурация без доменов не делает DNS-запросов и сохраняет
исходные байты. Индекс интерфейса, Wi-Fi и адрес домашнего роутера не сохраняются.

При ошибке DNS, пустом ответе, FakeIP или адресе самого TUN запуск останавливается
с объяснением. Не используется молчаливый переход шлюза на обычные VPN-правила.
Можно указать известный настоящий IP. Автоматического обнаружения всех
корпоративных доменов и глобального исключения VMware или российских сетей нет.

## Проверки

- Qt-диалог: сохранение, отмена, отсутствие изменений, ошибочный ввод, ошибка
  записи и повтор, защита остальных настроек и файла маршрутов, блокировка
  временного файла Windows. Файл EXE приложения и настоящий профиль не запускаются.
- Настоящий ConfigBuilder: домен и IP добавляются к прежним OS-исключениям,
  пользовательская схема сохраняется, ошибочный ввод не попадает в ядро.
- Ядро: новые A/AAAA после переподключения, дедупликация, DNS-ошибки/таймаут,
  защита TUN/FakeIP, неизменность обычных маршрутов и других полей JSON.
- `TestWindowsRealTunGatewayExclusion`: настоящий System TUN только на
  одноразовых Windows CI runner. Проверяется реальный выбор интерфейса Windows:
  исключённый тестовый IP использует исходный физический маршрут, соседний IP
  остаётся в TUN. После закрытия/переподключения обновлённый DNS-адрес получает
  исключение, старое исключение исчезает. Пакеты на публичный NGate не отправляются.

VMware, NGate и сертификат пользователя в CI не устанавливаются. Успешная
авторизация и полный корпоративный VPN после PIN требуют проверки у пользователя.
Причина первоначального отказа NGate через VLESS по представленному отчёту
не установлена; исправление обеспечивает явно выбранный обход перехвата TUN.
